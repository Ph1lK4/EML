# 启动已补全的实例

在“本地实例”选中实例，直接在启动卡片中选择“离线模式”或“正版模式”；“启动设置”页面也提供同一个选择。离线模式填写玩家名（默认 `Steve`），正版模式自动显示已登录的 Minecraft 玩家名，不需要输入。两个入口即时同步，切换模式保留离线名字。

打开“启动设置”可调整 Java 路径、初始/最大内存和附加 JVM 参数，再点击“使用当前设置启动”或上方“启动游戏”。默认内存为 1024–8192 MB。Java 路径留空时，按该实例生成配置声明的版本与架构自动匹配本机 Java。同一启动服务复用已发现的 Java 列表，避免每次重新搜索电脑；自动选择和手动指定都会在启动前重新查询实际 Java 版本与架构。

“保存设置”保存当前实例的偏好；直接启动使用当前输入，不自动保存。各实例的设置相互独立，位于实例目录 `.eml-runtime/launch/settings.json`。它不修改导入清单，也不属于导出包的原始文件完整性依据。设置文件读取失败时先修复文件，再点击“重新读取”，程序不会用默认值覆盖损坏文件。

## 启动流程

1. 读取组件元数据和已完成的运行准备记录，确认生成配置仍对应当前组件与平台。
2. 校验两份启动 JSON 的大小与 SHA-256，核对实例路径、主类和 Java 要求。检查类路径、本机库、日志配置及资源索引等关键文件的路径与大小。
3. 生成参数数组，使用选定实例的游戏目录启动 Java，持续读取标准输出和错误输出，记录退出码。

普通启动不调用实例完整检查器，不遍历模组、配置和全部资源对象，也不重新计算所有 JAR 的哈希。这是运行准备检查，不会产生完整检查的 `LaunchReady` 结论；同大小的内容损坏需要通过“完整检查”识别。手动“完整检查”及“补全实例依赖”的下载校验和最终完整复查继续使用原有严格规则。

Prism、Modrinth、CurseForge 和通用 ZIP 共用补全服务生成的主类、Minecraft 参数、模组加载器参数、类路径、本机库、日志配置和资源路径。通用 ZIP 从本地 `versions/<版本>/<版本>.json` 读取已声明的版本及依赖；不通过文件名猜测要安装的 Minecraft 或加载器版本。导入 ZIP 后会自动进入补全流程。

旧版已导入且运行文件齐全的 ZIP，在第一次点击“启动游戏”时会本地生成启动配置和本机库，并校验此次准备需要的运行文件；该兼容步骤不联网，也不扫描全部整合包内容。后续启动直接使用已有准备记录。只读 `PrepareAsync` 不执行此写入步骤；实际运行的 `RunAsync` 才会触发。运行文件缺失、元数据不明确或加载器不受支持时，会提示先补全或处理问题，不会仅凭目录中存在 JAR 就宣称能够运行。

附加 JVM 参数支持空白分隔及单双引号，例如 `-XX:+UseG1GC -Dexample="hello world"`。不会经过 PowerShell 或 cmd 解释。内存、主类、类路径及关键本机库和日志位置由启动器管理，冲突输入会明确报错。Java 9 以上使用临时参数文件避免 Windows 命令行长度限制；Java 8 使用直接参数，过长时提示失败。当前系统代码页无法表示的参数会明确报错，不静默替换字符。

## 运行状态和日志

“运行日志”显示最近 1000 行，完整进程输出写入 `.eml-runtime/launch/logs/<本次标识>.log`。界面进度有界缓冲，繁忙时可以省略中间显示，完整磁盘日志继续保留。启动准备会显示当前阶段；旧 ZIP 第一次准备本机库和启动配置所需的时间，与后续快速启动不同。

准备期间可取消，运行后可停止本次 EML 创建的游戏进程；不会按名称结束其他 Java 进程。建议优先在游戏中正常退出以保存进度。关闭 EML 时，如果仍在准备或运行，会询问是否取消/停止并等待清理。游戏运行期间禁止同时管理或改写实例。启动状态“进程已启动”仅表示 Java 创建成功；进入主菜单、加入服务器和存档加载是否成功，仍须结合游戏窗口及日志判断。

离线模式根据填写的玩家名创建离线身份；要求正版验证的服务器需要选择“正版模式”。正版启动使用账号服务提供的档案和有效会话，认证失败时不会自动切回离线。登录步骤见 [microsoft-login.md](microsoft-login.md)。

## 游玩后的文件变化

普通启动不会因为整合包配置与导入时不同而强制完整检查。手动检查、补全和安装时，正常设置变化、可信的一次性标记消耗与模组/运行依赖损坏仍由共享的 `InstanceFileChangePolicy`、`InstanceFileStatePolicy` 区分。具体边界见 [gameplay-file-policy.md](gameplay-file-policy.md)。不会覆盖玩家已修改的设置、重新写入已消耗的更新标记，或放宽普通下载文件的官方哈希验证。

## 代码位置

- `EML.Core/Minecraft/Launching`：设置、启动契约及共享输入验证。
- `EML.Infrastructure/Minecraft/Launching`：只读准备、Java 查询、设置持久化、参数文件、进程与日志管理。
- `EML.Infrastructure/Minecraft/Standard`：通用 ZIP 的本地版本解析、运行依赖补全与首次本地准备。
- `EML.App/ViewModels/InstancesViewModel.Launching.cs`：设置加载、界面命令、运行状态和日志显示。
- `MainWindow.xaml` / `.xaml.cs`：页面、服务组装和关闭时清理。

新增方法附有简短职责注释，启动相关实现独立于实例导入和下载。
