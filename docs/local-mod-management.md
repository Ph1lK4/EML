# 本地模组管理

在本地实例列表中右键目标实例，选择“模组管理”；也可以选中实例后点击启动按钮旁的“···”。首次打开面板时读取列表，搜索和筛选在内存中完成，不会在每次启动游戏时重新计算所有模组的哈希。

## 使用方式

- **添加本地模组**：选择 JAR/ZIP 文件并确认兼容性提示。文件被复制到当前实例的 `mods`，原文件保留。
- **接管**：仅适用于没有导入、平台或已有管理记录的额外文件。接管前需要用户明确确认，程序不会自行判断这个文件是谁添加的。
- **启用 / 禁用**：通过 `.disabled` 后缀切换，保留文件及其可信的内容基线。
- **移入回收区**：保存文件，并记录用户主动移除；补全实例不会重新安装它。
- **恢复**：恢复到移除前的启禁状态。同名或重复模组冲突时保留双方文件并报错。
- **恢复未完成操作**：程序中断后，按持久化的操作记录继续完成；文件被外部修改时停止，保留现场。

首版保护导入清单声明的模组。Prism 自用包中导入时已有的文件也受到保护，不能因为“在压缩包里”就认定它来自整合包作者。可写操作面向通过 EML 添加、明确接管或 GTNH 迁移加入的额外模组。

游戏、下载、迁移、导出与模组写入共用实例锁。其他启动器不遵守 EML 的锁，因此修改前也需要关闭由其他启动器运行的游戏。

## 显示与冲突检测

一个文件可包含多个模组 ID，启禁和回收仍以整个文件为单位。名称、版本无法读取时显示文件名和说明，不会从列表隐藏该文件。

扫描仅限当前实例的 `mods`；旧 Forge 还扫描当前 Minecraft 版本对应的子目录。其他版本目录、缓存及整个电脑不在扫描范围。无法确认加载器时保留只读查看。

添加、启用和恢复时检查文件名、已知模组 ID 和相同内容。无法读取模组 ID 时不能保证没有不同文件名的重复版本。基础元数据读取不等于验证模组版本、依赖或整合包兼容性；本功能不自动下载依赖或升级模组。

## 来源与完整性

三种信息独立保存：

1. 原始文件来源与可信的大小、哈希。
2. 用户期望的启用、禁用或移除状态。
3. 磁盘上实际存在、缺失或内容变化的状态。

管理记录位于实例的 `.eml-runtime/mods/state.json`，绑定原始导入清单。它不能覆盖官方文件要求，也不能把缺失自动解释为主动删除。用户模组使用确认时的大小与 SHA-256，禁用后仍按原要求校验。普通 CurseForge、Modrinth 文件继续沿用其各自的官方校验依据。

`InstanceEffectiveRequirements` 将管理记录应用到统一文件要求，检查、补全、安装和启动读取同一结果。文件操作期间保存 `.eml-runtime/mods/operation.json`；未提交完成时禁止其他流程使用不一致的文件状态。恢复只认可日志记录的内容，不覆盖外部新文件。

已明确接受的本地替换仍绑定原始文件身份。启禁改变存放位置，不会丢失这次明确接受的内容选择。

## 备份与 GTNH 迁移

EML 导出的 ZIP 在 `eml-instance.json` 的可选 `managedMods` 字段中保存管理状态和可信基线。实际启用或禁用文件随实例导出；重新导入后仍能管理。旧版清单没有此字段时保持原有行为。

**回收区不随实例导出。** 备份会保留“主动移除”的选择，避免导入后自动补回，但没有本机回收副本就不能恢复该文件。

GTNH 迁移仍需逐个勾选额外模组并确认兼容性风险。禁用模组以禁用状态迁入，新实例建立自己的迁入来源记录，不照搬旧实例的管理日志。已管理文件未接受的内容变化不能借迁移获得新基线；目标中已登记但移除或缺失的同名模组仍保留占位，不能被另一来源覆盖。

迁移后再操作模组会使原迁移恢复前提变化。此时“恢复上次迁移”会停止并保留文件，避免撤回仍被后续管理记录引用的内容。

## 代码位置

- `EML.Core/Minecraft/Mods`：界面条目、可携带的管理记录、路径规则和服务接口。
- `EML.Infrastructure/Minecraft/Mods`：轻量扫描、归档信息读取、管理状态、操作日志和文件服务。
- `InstancesViewModel.Mods.cs`：页面加载、筛选、命令与异步结果隔离。
- `LocalMod*Tests.cs`：文件操作、严格校验、备份、迁移、中断恢复与界面状态回归。

GTNH 迁移与本地模组管理共享元数据读取和重复判断，避免两处对同一模组给出不同结论。
