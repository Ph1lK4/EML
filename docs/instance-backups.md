# 实例备份与恢复边界

## 当前支持范围

导入与 ZIP 导出共用 `InstanceArchiveLimits`，当前生产限制保持不变：

- 最多 100,000 个 ZIP 条目，文件和显式目录条目都计数。
- 包内文件未压缩总量最多 50 GiB；不是 ZIP 压缩后的大小。
- EML 实例清单最多 64 MiB、100,000 条文件需求。
- 平台原始 JSON 清单最多 8 MiB。会由 EML 改写名称的 Prism `instance.cfg` 仍限制为 1 MiB。

这些限制分别约束归档、元数据和解析成本，不能互相替代。即使 ZIP 未达到条目或大小上限，路径冲突、非法元数据或恢复后清单超限也会被拒绝。归档中的字段不能放宽限制；内部小额度构造器仅用于测试。

## 导出流程

1. 验证实例和目标路径、取得实例操作锁，拒绝链接路径、写入实例自身以及覆盖已有备份。
2. 固定实际导出计划。排除原有策略规定的根目录 `.eml-runtime` 派生状态，保留游戏数据、隐藏文件和空目录。生成备份清单一次，并以生成后的真实字节数统计额度，不再使用旧清单长度估计。
3. 超限则在创建临时 ZIP 前失败，说明限制与相关路径，不自动删除、遗漏存档或其他用户数据。
4. 向目标目录内唯一的临时 ZIP 流式写入。逐文件核对计划长度与修改时间，并检查实际读取长度和总额度。
5. 关闭临时 ZIP，调用与导入相同的归档解析、路径布局和恢复元数据预检。恢复说明、文件记录以及 Prism 配置生成造成的清单增长也纳入检查。
6. 再次核对源目录增删、文件长度和修改时间，确认没有检测到变化后才发布正式 ZIP。发布不会覆盖同名文件。

取消或失败不会改动源实例及已有备份，并尝试清理本次临时 ZIP。异常情况下若文件被其他进程锁住，临时文件可能无法清理，但不会以正式备份名称发布。提交后的 UI 完成通知异常不将已发布的备份改报为导出失败。

## 备份不等于重新授权文件

备份允许保存玩家修改后的实际文件。原始来源、官方哈希、包内基线和用户已确认的替换记录继续保留；不会用当前文件摘要替换官方要求，也不会把未登记文件自动标为可信替换。重新导入后完整性状态仍是 `NotChecked`，由既有检查与变更策略处理。

## 检查能够保证什么

发布前检查针对当前版本导入器的结构与恢复元数据兼容性，并非逐文件完整解压演练，也不保证游戏可启动、远端依赖仍能下载、其他电脑空间足够，或未来任意版本的恢复行为。

实际恢复会再次校验归档，并在流式解压时核对每个条目的实际长度。恢复名称、备份文件名变更也可能影响极接近上限的元数据大小，因此每次导入都会重新进行预检。源文件变化检测使用长度与修改时间，不能替代关闭正在运行的游戏和其他写入程序。

## 大型实例的下一阶段

本次没有提高 100,000 条目 / 50 GiB 的生产上限，也没有添加“确认后无限放行”。超限实例将明确失败，不能产生看似成功、却超出当前恢复能力的备份。

后续开放大型实例模式前，需分别验证归档条目数、清单内存开销、真实大文件流式处理、取消、磁盘不足及恢复耗时，再提供明确、有限的容量档位与用户确认。50 GiB 边界目前采用声明长度测试，并非已经完成 50 GiB 实例的端到端容量测试。
