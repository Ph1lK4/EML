# Java 环境下载

“Java 环境”页面同时提供本机检测和下载安装。选择 Java 主版本与架构，点击“查询官方版本”，确认版本及下载大小后点击“下载并安装”。当前入口提供 Java 8、11、17、21、25；某一版本或架构没有官方 Windows 包时会明确提示，不会改用不兼容的包。

下载来源为 Eclipse Adoptium 官方 API 返回的 Temurin Windows JDK ZIP。JDK 包含游戏所需的 Java 运行时。安装位置是启动器根目录下的 `runtimes/java`，不修改 `PATH`、`JAVA_HOME`、注册表，也不覆盖电脑里原有的 Java。

## 启动时缺少 Java

启动器根据实例已经生成的运行配置判断 Java 主版本和架构。当没有找到兼容 Java，或用户指定的 Java 路径失效、版本或架构不匹配时，会询问是否下载。

- 选择同意：查询兼容版本的官方包，下载安装并验证，然后用本次原有玩家身份、内存及 JVM 设置继续启动。只重试一次。
- 选择取消：不下载，也不启动游戏；可以前往“Java 环境”或“启动设置”手动处理。
- 下载失败或安装验证失败：显示具体原因和安装目录，不把未安装好的环境加入列表。

自动下载只使用实例明确允许的版本，不根据报错文字猜测版本。认证失败、模组冲突、运行文件缺失、内存参数错误或游戏已经运行后的崩溃，不会触发这个提示。

安装完成后，该环境直接加入 Java 列表；启动时下载的 Java 会用于本次实例的启动设置草稿。需要在重启 EML 后保留手动指定路径时，点击“保存设置”。没有指定路径的实例仍会自动检测并选择兼容 Java。

## 下载与安全

Java 压缩包进入现有下载任务中心，共用队列、优先级、限速、下载缓存和断点续传。官方目录查询、解压和验证不是文件下载，因此对应阶段会在 Java 页面或实例启动日志显示。

安装前校验官方大小与 SHA-256，再在独立临时目录解压。拒绝越界路径、链接和异常压缩包；验证 `java.exe` 的实际版本、架构和运行结果后才发布安装目录。失败或取消只清理本次临时安装内容，不删除用户原有 Java。再次安装同一包时会检查已经安装的内容，不仅凭文件夹名称认定可用。

## 代码位置

- `EML.Core/Java`：下载契约、包信息与可恢复的 Java 环境异常。
- `EML.Infrastructure/Java`：官方目录、安全安装及 Java 验证。
- `JavaSettingsViewModel` / `JavaEnvironmentView`：Java 大页面的检测、查询、下载和进度。
- `InstancesViewModel.Launching`：启动失败时的确认、下载安装与一次重试。

测试使用受控 HTTP、下载器与 Java 探测替身，不会更改真实系统环境或启动玩家的游戏。
