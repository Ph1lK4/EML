# GTNH 玩家数据迁移

本功能仅为本地 GTNH **客户端实例**提供数据复制，不更新模组版本，也不自动保证存档兼容。

## 使用步骤

1. 保留旧实例，另行导入新版 GTNH，并完成依赖补全。
2. 先成功启动新版，正常退出。迁移前必须关闭两个实例的游戏，包括由其他启动器启动的游戏。
3. 在实例列表选中**新版接收实例**，打开“GTNH 数据迁移”，点击“从旧 GTNH 迁入数据”。
4. 选择旧实例和完整客户端/服务器客户端模式，选择数据范围。若需要带入自己添加的模组，展开额外模组区，逐个勾选并单独接受兼容性风险。
5. 检查文件预览。默认保留新版冲突文件；勾选覆盖后才用旧版个人文件替换。修改语言项本身是单独选择的合并操作。
6. 完成后测试新版存档，暂时保留旧实例。版本跨度大时，按 GTNH 更新说明逐个大版本进入存档后再继续迁移。

当前识别需要 EML 导入清单中的 Minecraft 1.7.10、包内 `config/txloader/load/mainmenu/version.txt` 的 GTNH 版本标识，以及至少两个 GTNH 配置特征。不会仅凭文件夹名称识别。不能确认的旧版或自定义包不开放入口。基础数字版本降低时拒绝迁移；相同基础版本的 beta 等后缀不用于保证升级顺序或兼容性。

## 数据范围

| 数据 | 完整客户端默认 | 服务器客户端默认 |
| --- | --- | --- |
| 每个 `saves/<世界>/` | 选择各个世界 | 不选 |
| `saves/NEI/` | 全部 NEI 记录 | 仅 `saves/NEI/global/` |
| `journeymap/`、`visualprospecting/`、`TCNodeTracker/` | 选择 | 选择 |
| `options.txt` 的 `lang` 字段 | 选择 | 选择 |
| `servers.dat`、`BotaniaVars.dat`、售货机收藏、`schematics/` | 存在时选择 | 不选，可手动选择 |
| 完整个人设置、截图、历史备份、光影包及其设置 | 不选，可手动选择 | 不选，可手动选择 |
| 自己额外添加的模组（逐个选择） | 不选，需确认兼容风险 | 不选，需确认兼容风险 |

完整个人设置是单独的可选组：`options.txt`、`optionsnf.txt`、`localconfig.cfg`。它可能覆盖新版默认值，且 `options.txt` 中的资源包引用不代表对应资源包也会复制。完整设置与语言项同时选中时，只执行完整设置复制。

同名世界始终复制到独立的 `世界名 (迁入 N)` 目录，不按文件合并世界。默认冲突策略对地图等其他目录按文件生效；如果需要沿用旧个人记录，可在预览后明确选择覆盖。

不会整目录复制 `mods/`、任意 `config/`、`scripts/`、资源包、完整汉化覆盖内容或启动参数。仅迁移明确勾选的额外模组及少数个人数据路径，例如 `config/vendingmachine/favourites` 和可选的 `config/shaders.properties`。本功能不负责服务端 `World`、UUID 缓存、缺失方块确认、任务书重置、汉化包下载或安装。

## 可选的额外模组

“迁移自己添加的模组”默认折叠，全部候选默认不选。只列出 `mods/` 和 `mods/1.7.10/` 中的 `.jar`、`.zip` 文件及其 `.disabled` 形式，保留原路径和禁用状态。不会复制模组配置、升级版本或补齐依赖。

**迁入模组可能与新版 GTNH、加载器或其他模组不兼容，导致崩溃、无法加入服务器或存档异常。** 勾选模组后必须单独确认风险，才能生成预览；请保留旧实例，先用存档副本测试。

Prism 导出的包可能已经带有玩家添加的模组，导入记录不能判断这些文件原本是否属于作者发布包。候选会区分“导入后新增”“此前手动迁入”“导入时已存在，需确认是自己添加”，最终由玩家逐个选择；不会自动把整份旧模组列表带入新版。

新版有同名模组（忽略 `.disabled` 后缀和目录）、相同 SHA-256 内容或已识别的相同 `mcmod.info` 模组 ID 时，预览显示跳过原因，始终保留新版；普通覆盖开关对此无效。新版清单或此前迁移记录已声明但暂时缺失的同名模组也受保护。没有可读模组 ID 时，无法排除不同名称、不同内容的重复版本，预览会明确说明；这些检查不代表兼容性检测通过。

额外模组使用独立的 `gtnh-extra-mod-v1` 记录，映射为严格的 `UserLocalImport` 内容文件，要求 Size + SHA-256。它们不会获得存档文件的可变或可删除许可；后续检查发现丢失或更改时会提示处理。用户明确接受的新文件仍按新的严格摘要校验，并随 EML 备份往返保留。原包及官方文件的来源和摘要保持独立。

额外模组参与同一迁移事务；取消或恢复会把本次新加入的模组移入事务恢复目录，并恢复对应来源记录。如果迁移后又修改了模组或接受了其他替换，会保留这些后续变更并拒绝自动撤销。

## 语言与汉化

默认只从旧 `options.txt` 读取唯一有效的 `lang` 值，并修改新版对应字段；新版其他选项、换行和 UTF-8 BOM 保留。没有目标文件或目标语言字段时补上该字段。无法可靠解析时停止这项迁移，用户可以取消选择语言继续迁移其他组。

**保留中文偏好不等于安装完整汉化。** 新版最终显示哪些汉化内容，取决于新版自身资源及用户另外安装的适配汉化；不复制旧版汉化包。

## 恢复与数据保护

- 执行时重新验证预览。先暂存、核对 SHA-256 并备份目标原件，再逐文件提交。
- 事务日志、旧文件备份和撤回的新文件保存在接收实例的 `.eml-runtime/migration/transactions/<编号>/`。不会改写旧实例的游戏文件。
- 取消会尝试恢复已提交内容；进程中断后的未完成事务会阻止后续启动和补全，需点击“恢复上次迁移”。
- 完成后也可以恢复最近一次迁移，但文件在游玩后发生改变、或迁入世界产生新文件时，自动恢复会拒绝覆盖并保留当前进度。完成后恢复预检被拒绝不会将正常实例强制锁定。
- 新迁入世界恢复时只移走本次引入的文件，清理其中空目录，不递归删除玩家数据。备份保留，便于人工处理。
- EML 的启动、下载、迁移和实例管理共用启动器根目录 `.eml-runtime/instance-locks/` 下的操作锁。外部启动器不受该锁管理，仍须用户正常退出游戏。

## 与来源校验和备份的关系

原始 `eml-instance.json` 的来源、大小和官方摘要保持不变。迁移记录保存在独立的 `player-data.json` 中，绑定原始清单指纹。

检查、补全和备份通过统一有效需求选择器识别 `MigratedPlayerData`：复制时严格验证 Size + SHA-256，后续允许这些明确迁入的玩家数据正常修改或删除，不自动从旧包复原。未迁入的普通官方文件仍执行原有严格规则。用户后来明确接受的不同本地替换仍使用自身严格摘要。

导出 ZIP 携带独立的可移植迁移用途记录，同时保留原始来源要求。重导入后延续玩家数据策略；本机恢复日志、旧文件备份和锁不包含在导出 ZIP 中。备份不是运行依赖打包格式，实例外的共享文件仍遵循原有导出规则。

启动只读取迁移状态摘要和现有来源元数据，不为本功能重新扫描/计算全部世界文件的哈希。预览、执行复核和恢复会读取选中数据，因此大型世界需要相应的磁盘时间和备份空间。

当前上限为单次 200,000 个文件/目录项、4,096 个世界组；EML 完整实例清单的本地保存、导出和备份导入共用 64 MiB 上限，并使用紧凑 JSON 保存，兼容旧的缩进格式。Prism、Modrinth、CurseForge 的原始平台清单仍受 8 MiB 限制。ZIP 导入仍限制 100,000 个条目、解压后总量 50 GiB。超限时明确报错，不静默截断文件或来源记录。备份及历史事务需要保留足够磁盘空间；历史事务不自动清理。
