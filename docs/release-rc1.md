# EML 1.0-RC1 发布与验收

`1.0-RC1` 是候选测试版，不是已经完成所有环境验收的正式版。

## 发布约定

| 项目 | 约定 |
| --- | --- |
| 面向玩家的版本 | `1.0-RC1` |
| 产品 / SemVer 版本 | `1.0.0-rc.1` |
| 程序集 / 文件版本 | `1.0.0.0` |
| 平台 | Windows x64 |
| 交付方式 | 便携 ZIP，完整解压后运行 `EML.App.exe` |
| .NET | 自包含发布，随包附带所需运行时；玩家不需要安装 .NET SDK 或 Visual Studio |
| Java | 不随启动器包附带；在“Java 环境”下载，或在启动时按提示安装所需版本 |

发布包命名为 `EML-1.0-RC1-win-x64.zip`。不得把开发项目目录、曾运行过的程序目录或历史发布目录直接压缩后当作新版发布包。

维护者从仓库根目录使用 `tools/Build-Release.ps1` 统一构建。构建工具需要 .NET SDK 和 PowerShell 7，这些是维护者工具，不是玩家运行要求。公开微软应用配置随包分发；本机加密构建输入只供编译使用。

```powershell
# PowerShell 7；先按现有 Configure-CurseForge.ps1 配置加密构建凭证。
./tools/Build-Release.ps1
# 默认输出 artifacts/releases/EML-1.0-RC1-win-x64.zip 及 .zip.sha256。
# 已存在的发布包不会覆盖；重新打包时指定新的 -OutputDirectory。
```

旧的 `Build-CurseForge.ps1 -Publish` 也会转到这个统一流程。`-SkipTests` 仅供调试构建，清单会如实记录未执行测试，不应据此宣称通过发布验收。

发布过程应从新建空目录生成内容，检查版本、x64 架构、自包含运行时与文件边界，再生成逐文件 SHA-256 清单和 ZIP 校验值。校验值可以检查传输损坏或内容变化，但不能代替数字签名、证明发布者身份，或保证第三方模组安全。

新版发布包同时包含 EML 的 GPL 许可证 `LICENSE`、对应源码定位说明 `SOURCE.txt`、隐私、安全报告和卸载说明，以及第三方组件的许可证与声明。`SOURCE.txt` 应给出实际构建提交及其源码地址；GitHub Release 标签必须指向同一提交，不能只指向持续变化的分支。发布页应提供对应源码的下载入口。普通 CI 上传的是测试报告，不是面向玩家的完整发布包。

玩家可在 PowerShell 中运行 `Get-FileHash -Algorithm SHA256 -LiteralPath '实际下载的 ZIP 路径'`，与维护者提供的 `.zip.sha256` 比较。维护者使用 PowerShell 7 运行 `./tools/Test-ReleasePackage.ps1 -Path '解压后的 EML-1.0-RC1-win-x64 目录'`，可再次验证完整清单；`Test-ReleasePackage.Tests.ps1 -PackagePath '同一目录'` 还会在临时副本中测试污染、篡改和升级保留。不要对已经使用过、包含用户数据的安装目录运行“全新发布包”审计。

## 玩家首次使用

1. 将 ZIP 完整解压到自己有写入权限的目录，例如用户文件夹内的 `EML`。不要放在 `Program Files`、Windows 系统目录或只读位置。
2. 运行解压目录内的 `EML.App.exe`。不要在压缩软件中直接运行，不要只复制一个 EXE。
3. 导入整合包，或在“下载实例”“GTNH 专区”创建实例。启动器包本身不包含 Minecraft、模组包或个人实例。
4. 在“Java 环境”安装适合实例的 Java；也可以在启动实例时按提示确认下载。拒绝或取消不会代替用户继续安装。
5. 确认启动模式和玩家身份。正版模式需要有效账号和对应服务授权；离线名字不是正版登录，通常不能进入要求正版认证的服务器。

首次下载需要网络和足够磁盘空间。自包含 .NET 只解决启动器自身的运行时依赖，不代表已经下载游戏或 Java，也不保证所有整合包和服务器都兼容。

不要求以管理员身份运行。若 Windows 或安全软件阻止启动，先核对下载来源与校验值，保留完整提示交给维护者；不要关闭系统防护来强行运行。本次 RC1 未进行代码签名。

## 升级时的数据边界

Release 版以 `EML.App.exe` 所在目录为启动器根目录。它不会像 Debug 开发版那样向上寻找项目目录。

| 数据 | 位置 | 更新时的处理 |
| --- | --- | --- |
| 实例、世界存档、地图、截图、游戏设置 | `instances/<实例>/` | 整个目录保留 |
| 启动参数、玩家模式、公开账号身份、上次启动记录和 Java 路径 | `instances/<实例>/.eml-runtime/launch/settings.json` | 保留；不含登录令牌 |
| 来源记录、用户替换、模组回收区、迁移记录和备份 | `instances/<实例>/.eml-runtime/` | 整体保留，不能当普通缓存删除 |
| 并发数、限速等下载设置 | `settings/downloads.json` | 保留 |
| 启动器下载的 Java | `runtimes/java/` | 保留 |
| 下载缓存、断点文件、整合包原包 | `cache/` | 建议保留；原包还可能用于恢复包内文件 |
| 全局运行状态、图标缓存、锁目录 | 根目录 `.eml-runtime/` | 原样保留，不在升级中清理 |
| 导入工作目录 | 根目录 `.eml-imports/` | 不在升级中粗暴清理；异常遗留应单独诊断 |
| 多个微软账号的加密凭证集合 | `%LOCALAPPDATA%\EML\accounts\microsoft.dpapi` | 不在发布包内；同 Windows 用户更新继续使用，兼容读取旧单账号记录 |

升级步骤：

1. 正常退出游戏，结束下载、导入和迁移任务，再退出 EML。
2. 复制备份整个旧 EML 文件夹。仅“导出实例 ZIP”不能替代这份备份，因为实例根 `.eml-runtime` 中部分本机设置与事务状态不在导出范围内。
3. 把新版 ZIP 解压到另一个临时目录，核对其中的发布清单。
4. 保持旧 EML 的安装路径不变，把新版程序文件复制进去，仅覆盖发布包中同名的程序文件。发布包不应包含上述用户数据目录。
5. 不先删除旧 EML 文件夹，不使用镜像同步、清空目录或 `robocopy /MIR`。不要合并、覆盖其他人的实例或账号文件。
6. 启动新版，核对版本、实例数量、玩家名 / 登录模式、内存 / JVM 设置和 Java 路径，再使用存档副本测试游戏。

RC1 采用手动覆盖程序文件的升级方式，不提供事务式自动更新。若测试失败，先正常退出，保留失败现场，再从升级前的整目录备份恢复。不要让两个版本同时操作同一份实例。

搬迁目录或换电脑是另一种操作：明确保存的 Java 绝对路径、整合包原包位置可能失效，需要重新选择。Windows DPAPI 凭证不能承诺跨用户或跨电脑解密，应重新登录。下载任务列表是进程内状态，不承诺升级后自动恢复所有任务；保留缓存有助于重新发起下载时复用文件。

多账号凭证首次成功修改后会从旧单账号格式写为新版集合。回退到不支持多账号的旧程序时，不保证旧程序能读取新版集合；不要为回退清空凭证或覆盖仍在使用的账号文件，必要时在确认版本支持后重新登录。账号集合与游戏存档是不同的数据，移除账号不会删除游戏存档。

## 发布前的隐私检查

发布包不得带入以下内容：

- `instances`、`settings`、`runtimes`、`cache`、任何 `.eml-*` 数据目录。
- 微软账号文件、访问令牌、个人游戏日志、服务器记录、截图、存档或测试实例。
- `.eml-build` 加密构建输入、独立 API 密钥文件、PDB、binlog、测试结果、源码或测试程序集。

`microsoft-login.json` 只允许公开的应用 `clientId`，不能包含账号信息或 client secret。

CurseForge 授权暂时沿用当前程序集内嵌方案。这意味着发布程序仍包含开发者授权，不能声称“密钥绝对隐藏”或“无法提取”；仍有被提取、滥用及吊销的风险。本次发布包审计防止误带私人数据与独立凭证文件，不改变该方案的保密边界。

## 干净电脑验收清单

当前没有可用的干净测试机或虚拟机，用户已选择先交付测试包与步骤。以下检查仍待完成；开发机启动、自动化测试和清空 PATH 不能代替它们。不要卸载或破坏开发机已有 Java / .NET 来模拟。

建议使用干净安装的 Windows x64 测试机或一次性虚拟机，使用普通用户账户，并记录 Windows 版本、CPU 架构、包的 SHA-256 和测试时间。

| 检查 | 操作与预期 | 状态 |
| --- | --- | --- |
| 环境基线 | 确认没有 Visual Studio、.NET 10 共享运行时和 Java；不能只凭 `java` 命令找不到就认定完全没有 Java | 待测 |
| 首次运行 | 解压到可写目录，运行 EXE；不要求安装 .NET、不要求管理员权限，界面正常显示 | 待测 |
| 断网启动 | 断网时仍能打开启动器；网络功能失败有明确说明，不出现无响应或误报成功 | 待测 |
| Java 缺失 | 导入小型测试实例并尝试启动；提示所需 Java，取消后保持未启动 | 待测 |

| 升级保留 | 预先设置独特玩家名、内存、限速，并保存测试存档；按上述步骤升级后逐项核对数据未丢失 | 待测 |
| 账号流程 | 由测试者本人添加两个正版账号，让不同实例分别使用；切换默认并重启 EML 后核对选择仍独立，再实际进入正版服务器。移除所选账号时不能自动换人；不提供密码或令牌给维护者 | 待测 |

测试报告写明实际结果与失败阶段，不要只写“能打开”。问题反馈提供 EML 版本、Windows 版本、操作步骤及已脱敏的错误文字；不要发送账号凭证、完整私人目录或未检查的整份日志。

只有上述待测项得到实际结果后，才能决定是否发布后续 RC 或正式 1.0。制作本地候选包不等于已经向 GitHub 发布，也不等于已经完成第三方 API、所有整合包和服务器的端到端验收。
