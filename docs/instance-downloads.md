# 下载实例

左侧“下载实例”页面可以从 Modrinth、CurseForge 获取整合包，也可以安装 Mojang 提供的 Minecraft Java 版原版。它创建新的实例，不覆盖现有世界。

## 使用流程

1. 选择来源，输入整合包名称或原版版本号，再点击搜索。整合包可按 Minecraft 版本、加载器及排序筛选；CurseForge 加载器筛选需同时提供游戏版本。
2. 在左侧选择项目，右侧选择具体发布版本。图标、名称、简介、作者、版本和文件大小来自对应平台。结果及版本列表可继续加载后续页。右侧“项目介绍”按需显示平台完整正文，作者提供的中文会直接保留；只有英文时保留英文，不使用额外翻译或本地收录名单。
3. 点击“下载并创建实例”。下载并校验原包后，确认实例名称；EML 复用本地导入器，再自动补全模组、客户端、类库和资源等支持的运行依赖。
4. 下载或补全中可取消。已经导入的实例和已下载文件保留；在本地实例中右键选择“补全实例依赖”继续。完成结果区仍会显示缺失文件、运行依赖失败和手动处理项，不会把“包下载完成”视为可以启动。
5. Java 与账号继续在对应页面配置，启动参数在 Java 环境下方的“启动设置”大页面按实例分别设置。这里不会自动安装 Java 或登录账号。

官方原版默认只显示正式版，可选择包含快照/预发布版本；老 Alpha/Beta 未列入该页面。原版安装采用官方目录中的精确版本 JSON，由现有标准版本安装器解析。特殊历史版本是否可以安装取决于运行解析器支持，无法识别时会明确报告而不会生成假的就绪状态。

## 来源与文件校验

- Modrinth 只下载唯一主 `.mrpack` 或唯一可用 `.mrpack`，使用该文件的大小与 SHA-1/SHA-512。
- CurseForge 只下载客户端 ZIP，沿用当前构建的 CurseForge 授权，验证官方大小与 SHA-1。服务端包不会出现在可安装版本中。官方未提供第三方下载时显示原因与项目网页，不拼接 CDN 地址。
- CurseForge 包内受限模组仍使用现有精确匹配的 Modrinth 备用下载规则；该规则不会凭整合包同名选择另一个平台的不同包。
- Mojang 目录固定来自官方版本目录。版本 JSON 使用目录给出的 SHA-1 校验，因目录不提供 JSON 大小，额外限制为 8 MiB；其中的客户端和资源仍按官方大小、摘要下载。
- 确认下载时重新读取固定项目/版本信息。搜索结果中的旧 URL 不能直接作为下载依据，不跨来源合并摘要。

原包保留在启动器 `cache/instance-archives`，供 Embedded 文件恢复使用。目录名称由固定身份与摘要生成，远端文件名不会成为任意写入路径。每次复用缓存重新校验；损坏的旧缓存保留，新下载另存。若需要恢复原包内文件，请保留缓存。

## 代码组织

- `EML.Core/Minecraft/Catalog/InstanceCatalogModels.cs`：来源、项目、发布版本及目录/归档接口。
- `EML.Infrastructure/Minecraft/Catalog/InstanceCatalog.cs`：三个来源的查询、分页和固定版本核对。
- `EML.Infrastructure/Minecraft/Catalog/InstanceArchiveService.cs`：原包缓存、校验和原版导入源准备。
- `EML.App/ViewModels/InstanceDownloadsViewModel.cs`、`Views/InstanceDownloadsView.xaml`：查询、版本选择、进度与取消。
- `InstancesViewModel.DownloadInstanceAsync`：持续持有实例忙碌状态，接入已有导入与自动补全，关闭窗口时等待退出。

网络请求只在打开下载页面或执行对应操作时开始。切换筛选会清空旧选择，旧响应不会重新填充列表；切换主页面只取消目录查询，已确认安装继续执行。

完整介绍与版本列表分别读取。介绍失败时可点击“刷新介绍”，也可直接查看项目网页；不会因为介绍不可用而阻止选择版本或下载。正文以可复制的纯文本显示，保留作者的多语言段落，不执行脚本或自动加载图片。搜索关键词原样传给平台，能否搜索中文名称取决于平台索引。
