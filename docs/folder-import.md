# 从其他启动器复制实例

在“本地实例”点击“从其他启动器导入”，选择发现的实例，再预览并确认复制。不需要先导出 ZIP；原来的启动器和实例继续保留。

## 使用步骤

1. 先正常退出该实例的游戏，等待存档写入结束。复制期间不要从其他启动器运行、更新或编辑它。
2. 在发现窗口选中实例。找不到时，点击“选择实例 / 启动器文件夹”，选择便携版的数据目录、实例目录或 `.minecraft`。
3. 共享 `.minecraft` 可能显示多个版本，请选中本次需要的版本。EML 不会把几个版本混成一个实例。
4. 核对游戏目录、目标路径、名称、文件数量、空间和跳过项目，确认游戏已退出后开始复制。
5. 文件复制成功后自动进入已有的依赖补全流程。此阶段可能联网；下载失败或取消会保留已复制的实例，可稍后继续补全。

识别成功不代表一定能启动。缺少版本描述、未知加载器、损坏元数据或启动器特有安装步骤会给出说明，不能靠模组文件名猜测一个原版版本启动。

## 本轮支持的布局

| 来源 | 识别依据与边界 |
| --- | --- |
| Prism / MultiMC / PolyMC | `mmc-pack.json`、`instance.cfg` 和 `.minecraft` / `minecraft`；保留本地模组、补丁与组件，重建安全的名称配置。 |
| Modrinth App | 旧版 `profile.json`，或紧邻 `profiles` / `instances` 的 `app.db` 中已安装版本记录；支持 `profiles` 表及 `instances` + `instance_content_sets` 表。 |
| CurseForge App | `minecraftinstance.json` 中游戏版本与 `baseModLoader`；现有 mods 原样复制，不把旧导出清单当成当前安装状态。 |
| ATLauncher | `instance.json` 中 Minecraft `id`、`launcher` 与加载器字段。 |
| GDLauncher | 旧版 `config.json` 的 `loader` 布局；Carbon 等其他数据库布局暂不承诺兼容。 |
| 官方 / PCL / HMCL / BakaXL 等标准布局 | `versions/<id>/<id>.json`；每次选择一个版本及其继承链，支持中文版本目录。不是按启动器品牌名称硬匹配。 |

这不是“市面上所有启动器的所有版本”保证。自动发现覆盖常见 Windows 数据位置；便携版请选数据目录。任意自定义游戏目录、Modrinth 数据库与游戏目录分开放置、启动器特有的安装脚本或未知元数据，应先用原启动器导出包。标准目录同时有共享与隔离数据时会列出两个候选，必须核对路径后选择。

Modrinth 数据库只查询实例名称、路径和运行组件，不查询账户表，不 checkpoint，不创建 SQLite 共享内存文件。检测到未合并的 WAL / journal 或数据库仍被使用时，请正常退出 Modrinth 再试；不要自行删除数据库日志。未知架构会提示改用导出包。

## 保留与排除

- 复制支持布局中的模组、配置、存档、地图、服务器列表、资源包等游戏内容。
- 不导入启动器账号凭证、登录令牌、应用数据库、本机 Java 路径及启动前后命令。请在 EML 中重新选择账号和启动设置。
- 不移动源实例，不覆盖 EML 同名实例，不创建中间 ZIP。
- 符号链接、目录联接及互相包含的来源和目标会被拒绝，避免复制到实例之外或无限递归。
- 自动发现只检查常见位置和有限的已知实例容器，不搜索整块磁盘。便携版、自定义目录和暂不支持的元数据格式需要手动选择或使用原启动器导出包。

## 文件来源与恢复

没有 EML 来源清单的文件夹，现有文件记录为 `LocalFolderImport`，使用本次复制时的大小与 SHA-256。它表示“用户选择的本地副本”，不代表已获得 CurseForge、Modrinth 或模组作者的官方认证。运行依赖的官方下载校验不变。

配置与玩家数据遵循统一的可变规则；模组、脚本、数据包和运行文件不能因为来自本地文件夹就免除完整性检查。缺失本地文件时，不会自动读取旧实例或按文件名下载不同内容替代。可使用 EML 导出的备份恢复，或由用户明确选择修复文件。

外部实例已经含有合法 `eml-instance.json` 时，也可以发现并复制导入。Prism 的来源列会显示“保留 EML 来源”，名称以当前 `instance.cfg` 为准；读取器会核对游戏目录、Minecraft 和组件版本与已有清单一致。清单损坏或版本冲突时会显示原因，不会静默丢弃记录再按普通 Prism 导入。

这一分支保留原包及平台文件的大小、摘要、下载身份、原压缩包名称和恢复条目，并将有效的用户替换、迁入玩家数据、模组启禁／移除及新增资源来源携带到副本。不会根据当前磁盘内容改写已记录摘要：原本缺失或不匹配的文件仍需后续检查处理，复制成功不等于内容检查通过。原清单未登记的新文件也会复制，但不重新登记为原包内容。

本机 `.eml-runtime` 派生状态不直接复制，其中可移植来源由上述清单保存；回收区实际文件、迁移撤销备份和原包绝对路径记录仍留在源实例，不随本次导入迁移。保留原归档条目不代表原 ZIP 已在新位置可用。普通 Prism 名称配置会重建以去掉本机启动设置；若 `instance.cfg` 有独立严格校验来源，导入会拒绝自动改写并提示核对。

截图、世界和地图等可变玩家数据不会因为用户删除而成为启动必需项；模组、脚本、数据包仍保持严格内容要求。现有账号文件、旧日志和原启动器 Java 设置不属于本次搬迁内容。普通模组自行保存的私有配置不在启动器账户识别范围内，请只导入可信实例。

## 大小与取消

目录导入沿用当前导入／导出的共同额度（包括生成的清单与目录条目）：最多 100,000 条目、50 GiB，另有清单大小限制。预览会提前检查，避免导入后无法导出为可回导备份。真实写入仍可能受磁盘剩余容量、文件锁及权限影响。

提交前发生失败或取消，只清理本次暂存副本；已成功提交后的依赖补全失败，不回滚玩家已导入的数据。复制前后会复查文件集合、大小、修改时间和版本元数据，但这不能替代正常关闭游戏，也不是实时备份正在使用的存档。
