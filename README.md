# EML Launcher

简体中文 | [English](README.en.md)

EML 的目标是成为一款 **中国 GTNH 玩家专属启动器**，基于 Windows 桌面平台，围绕 GTNH 的安装、启动、长期游玩和版本更新提供更方便的使用体验。

GTNH 的游玩周期很长，玩家在积累存档、地图记录和个人设置的过程中，也难免遇到整合包更新。每次换用新版实例，都要重新整理这些本地数据。因此，EML 将“导入新版、补全依赖、迁入旧版玩家数据”作为重要的使用流程，让长期游玩的记录更容易延续到新版本。

我们希望即使不熟悉电脑操作的玩家，也能更轻松地开始和持续游玩 GTNH。项目目前保留多种整合包格式的导入能力，后续开发将优先围绕中国 GTNH 玩家的实际需求展开。

项目目前处于开发阶段，界面与兼容性仍在完善。

## 当前功能

- **GTNH 玩家数据迁移**：在旧版与新版 GTNH 客户端实例之间迁移存档、地图记录、个人设置和语言偏好，支持预览、备份、恢复，以及可选迁移玩家额外添加的模组。
- **Java 检测**：启动时自动检测本机 Java，支持手动选择，以及根据实例要求自动匹配已安装的 Java。
- **本地实例管理**：识别启动器根目录下 `instances/` 中的实例，展示名称、Minecraft 版本、加载器、实例路径和游戏目录，支持重命名、删除及 ZIP 导出备份。
- **多格式导入**：支持 Prism ZIP、Modrinth `.mrpack`、CurseForge ZIP 和通用游戏目录 ZIP，导入后自动开始依赖补全。
- **下载与补全**：根据整合包清单下载所需模组和受支持的运行依赖；部分 CurseForge 文件无法直接下载时，尝试从 Modrinth 获取哈希与大小一致的文件，无法匹配则提示处理。
- **文件完整性检查**：提供快速检查和完整哈希校验，区分不同文件来源、用户明确接受的替换及允许正常变化的玩家数据。
- **游戏启动**：按实例配置玩家名称、Java、内存和附加 JVM 参数，查看运行日志；日常启动采用必要的运行准备检查，不重复执行整包哈希检查。

微软正版登录流程已经接入，当前仍在完成 Minecraft API 准入和实际登录验证，暂不作为已可用功能。配置与进展见 [微软账号登录说明](docs/microsoft-login.md)。

## GTNH 实例数据迁移

迁移需要同时保留两个实例：**带有游玩数据的旧版 GTNH**，以及**已导入、补全并试运行成功的新版 GTNH**。关闭两个实例的游戏后，选中新实例，在“GTNH 数据迁移”中点击“从旧 GTNH 迁入数据”，选择旧实例和迁移内容，确认预览后执行。

- **延续游玩记录**：按需迁移单人存档、NEI 记录、JourneyMap 地图、矿脉与神秘节点数据，以及部分个人设置、服务器列表等。
- **照顾服务器玩家**：提供“服务器客户端”模式，默认选取本机地图、NEI 全局记录和语言偏好等数据，方便玩家更新自己的客户端。
- **保留个人习惯**：可迁移中文语言偏好，并逐个选择自己额外添加的模组。额外模组可能与新版不兼容，需要确认风险后迁移。
- **保留旧实例与恢复依据**：复制选定数据，不改写旧实例的游戏文件；迁移前提供预览并备份目标原件，同名世界另存为独立目录，支持恢复上次迁移。迁移后若数据又发生变化，自动恢复会拒绝覆盖，保留后续进度。

此功能仅面向 GTNH 客户端，不迁移服务端，也不复制或安装完整汉化包。保留中文偏好后，新版的汉化内容仍取决于其自身资源及另外安装的适配汉化。跨版本存档兼容性仍需遵循 GTNH 更新说明；版本跨度较大时，应逐个大版本更新并验证存档。

详细范围和操作说明见 [GTNH 玩家数据迁移](docs/gtnh-player-data-migration.md)。

## 使用方式

1. 启动 EML，等待 Java 和本地实例检测完成。
2. 点击“导入实例”，选择整合包文件，等待导入及自动补全结束。
3. 查看补全结果；若有需要手动处理的文件，按提示处理后再次检查。
4. 在“启动设置”中选择 Java、设置内存与 JVM 参数，然后点击“启动游戏”。

开发调试时，实例默认保存在解决方案根目录的 `instances/`；发布版本使用启动器 EXE 旁的 `instances/`。

目前的兼容范围取决于整合包提供的元数据和已实现的加载器支持，并非所有 ZIP 或整合包都能直接补全运行。实例导出不包含实例目录之外的共享依赖。
