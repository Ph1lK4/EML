EML 1.0-RC2 · 升级与数据保留

推荐保持原安装路径，备份后只合并新版程序文件。
这不是自动更新，不会自动删除旧程序文件，也没有自动回滚。

从 RC1 / RC1-Logo1 升级

1. 正常退出 Minecraft，结束下载、导入和迁移，再退出所有 EML。
2. 复制备份整个旧 EML 文件夹，包含隐藏目录，确认副本可读取。
3. 将 RC2 ZIP 完整解压到另一个临时目录，核对同版本 SHA-256。
4. 将新版解压目录内的文件和文件夹复制到旧 EML 根目录，合并目录，
   只覆盖发布包内同名的程序文件。原来的玩家数据必须保留。
5. 运行根目录新的 EML.exe，确认显示 1.0-RC2。
   将旧快捷方式改为指向 EML.exe。
6. 核对实例、上次账号和模式、Java 路径、内存、JVM 参数及下载设置。
   第一次游戏测试请使用存档副本。

入口与目录的变化

RC2：EML.exe 是启动入口，app/ 存放程序、.NET 和语言资源。
玩家数据仍在 EML.exe 旁边，不迁入 app/。

旧 EML.App.exe、DLL 和语言目录可能仍留在根目录。这是保留旧文件
的结果，不代表 RC2 要使用它们。不要继续运行旧 EML.App.exe。
此流程不自动清理旧文件，因此升级后的目录可能比全新解压更杂。
如需后续清理，必须按旧发布清单逐项核对；不要按扩展名批量删除。

这些数据必须原样保留

- instances：全部实例、世界存档、地图、截图、游戏设置。
- 实例内 .eml-runtime：启动设置、来源和用户修改记录、模组回收区、
  迁移记录和备份；不是可以随意清理的普通缓存。
- settings：下载并发、限速等设置。
- runtimes：EML 下载的 Java。
- cache：缓存、断点文件及整合包原包；原包还可能用于文件恢复。
- 根目录 .eml-runtime 和 .eml-imports：保留，不在升级中粗暴清空。

不要先删除旧文件夹，不要“清空后解压”，不要使用镜像同步或
robocopy /MIR。不要让两个 EML 版本同时操作同一份实例。
“导出实例 ZIP”不能代替完整升级备份，部分本机设置和恢复记录
不在实例导出范围内。

账号在哪里？

微软账号集合仍在当前 Windows 用户的：
%LOCALAPPDATA%\EML\accounts\microsoft.dpapi

它不在发布包或 app/ 里。同一 Windows 用户升级继续使用；其他
EML 副本也会使用这个位置。换电脑或用户应重新登录，不要分享、
搬运或为升级清空凭证文件。

如果要换目录或换电脑

这不等同于同路径升级。Java 绝对路径、原整合包位置可能失效，
需要重新选择；账号应按需重新登录。保留缓存不代表全部下载任务
会自动恢复。请在旧目录保留期间核对新位置的实例和数据。

如果需要回退

先退出新版并保留错误信息，使用升级前的完整备份，避免混用
不同版本的 EXE 和 DLL。若已经继续游玩或更改设置，先另外备份
新增数据；不要用旧备份直接覆盖最新存档或设置。

原 RC1 的标签、原包与校验值保持不变。RC1-Logo1 和 RC2 各自有
独立版本、源码提交与 SHA-256，不能互换校验文件。
详细说明见 docs/release-rc2.md。

English: Close Minecraft and EML and back up the complete old folder.
Merge RC2 into the same path without deleting player data. Run the new
EML.exe and update shortcuts; old EML.App.exe and flat runtime files may
remain but are not automatically removed. Keep app/ intact. Do not use
mirror sync or mix binaries from different versions. Back up any new
player data before reverting to the pre-upgrade backup.
