EML 1.0-RC1 · 升级与数据保留

推荐升级方式：保持原来的安装路径，只覆盖新版程序文件。

1. 正常退出游戏，结束下载、导入和迁移，再退出 EML。
2. 复制备份整个旧 EML 文件夹，确认备份完成。
3. 将新版 ZIP 解压到另一个临时目录，核对发布清单。
4. 把新版程序文件复制到旧 EML 文件夹，只覆盖包内同名的程序文件。
5. 启动 EML，核对版本、实例列表、启动参数和 Java 路径。
   第一次进入游戏请使用存档副本。

不要先删除旧文件夹，不要“清空后重新解压”，不要使用镜像同步或
robocopy /MIR。不要同时用两个 EML 版本操作同一份实例。

这些数据必须保留

- instances：全部实例、存档、地图、截图和游戏设置。
- 实例中的 .eml-runtime：启动参数、用户修改记录、模组回收区、
  迁移记录和备份等。它不是可以随意清理的普通缓存。
- settings：下载并发数、限速等设置。
- runtimes：EML 安装的 Java。
- cache：下载缓存、断点文件和整合包原包；原包还可能用于恢复文件。
- 根目录的 .eml-runtime 与 .eml-imports：升级时原样保留，不粗暴清理。

“导出实例 ZIP”不能代替整目录升级备份：部分本机启动设置和恢复事务
不会进入实例导出包。升级前请备份整个旧 EML 文件夹。

账号在哪里？

微软账号凭证在当前 Windows 用户的：
%LOCALAPPDATA%\EML\accounts\microsoft.dpapi

它不在发布包或实例里。同一 Windows 用户升级继续使用；
换电脑或换 Windows 用户应重新登录，不要分享或搬运这个凭证文件。

如果要搬到另一个目录或另一台电脑

这不等同于原路径升级。你保存的 Java 绝对路径、原整合包位置可能失效，
需要重新选择。保留缓存不代表下载任务列表会全部自动恢复。

如果新版出现问题

先正常退出，保留错误提示，再使用升级前的整目录备份恢复。
RC1 目前是手动覆盖升级，没有事务式自动更新或自动回滚。
